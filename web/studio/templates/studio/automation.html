Automação ponta a ponta

Um botão para reconstruir ciência, modelos e operação 24h

Esta tela executa o fluxo completo em ordem segura: histórico ONS → tarifas → Climate Store local-first → clima e baseline de 10 anos → features E3 → validação Ridge/XGBoost → treino dos 24 horizontes para N, NE, SE/CO e S → seleção por WAPE → previsão meteorológica operacional → publicação do system_signal_v1.

Importante: o operacional só é publicado quando a carga ONS está suficientemente fresca e existe previsão meteorológica real para H01–H24. Se o ONS estiver defasado, a automação treina normalmente, mas bloqueia a publicação operacional em vez de fingir que o dado é atual.

O que o botão executa

Não é apenas uma sequência de scripts: cada bloco tem um gate e produz artefatos auditáveis.

Hiperparâmetros dos dois modelos
A primeira execução pode demorar para completar o backfill. Depois disso o Climate Store é consultado primeiro e apenas intervalos realmente ausentes podem acessar a rede. Em 429 persistente, o job passa para WAITING_RATE_LIMIT e retoma do checkpoint; não perde os batches concluídos. Para backfill nacional 0,1° de muitos anos, a API pública pode atingir o orçamento diário e um endpoint local/self-hosted é o caminho recomendado.
Baselines sem vazamento:

Para cada ano Y do histórico, a automação constrói o baseline com Y-10…Y-1. Ex.: 2023→2013–2022; 2024→2014–2023; 2025→2015–2024; 2026→2016–2025.
